**File 2: `docs/06-collections/02-java-collections.md`**

Frontmatter: `sidebar_position: 2`, `title: "Java Collections"`

Content sections:
1. **Opening (2-3 sentences):** BBj runs on the JVM and gives you direct access to the entire Java Collections Framework. For key-value storage, use `java.util.HashMap`. For a Java-native dynamic list alternative to BBjVector, use `java.util.ArrayList`. This chapter covers the patterns you will use most often.
2. **java.util.HashMap:** Show creating, populating, and reading. Use the verified HashMap/Iterator example from RESEARCH.md. Walk through: `use java.util.HashMap`, `new HashMap()`, `put()`, `get()`, `keySet()`.
3. **Iterating a HashMap:** Show the `keySet().iterator()` pattern with `hasNext()`/`next()`. Use the verified example from RESEARCH.md. Note: iteration order is not guaranteed (standard HashMap behavior).
4. **java.util.ArrayList:** Show creating and using ArrayList. Use the verified example from RESEARCH.md. Brief -- ArrayList is similar to BBjVector, the main difference is that ArrayList is a pure Java class while BBjVector is BBj-native.
5. **When to Use Which:**
   - **BBjVector** when working with BBjAPI methods that expect BBjVector (some BBj methods return or accept BBjVector specifically)
   - **java.util.ArrayList** when working with Java libraries that expect standard Java List types
   - **java.util.HashMap** for all key-value storage (the only recommended map type)
   - Note: BBjVector and ArrayList are largely interchangeable for most use cases
6. **Why Not BBjHashMap?** Brief note: `BBjHashMap` was renamed to `BBjspHashMap` in BBj 20.10. It was moved to the BBJSP (server pages) subsystem. For general-purpose key-value storage, use `java.util.HashMap`.

Cross-link to the [Java interop chapter](/object-oriented/using-java) for broader context on using Java classes from BBj.

Legacy callout: "Reading Legacy Code: BBjHashMap"
- Code written before BBj 20.10 may use `BBjHashMap` -- this still works but is deprecated for general use
- `BBjHashMap` was renamed to `BBjspHashMap` and restricted to the BBJSP subsystem
- When maintaining legacy code, consider migrating to `java.util.HashMap` if doing significant changes
- The API is similar: `put()`, `get()`, `remove()` work the same way

Content sections:
1. **Opening (2-3 sentences):** DIM arrays are BBj's fixed-size, typed arrays -- they predate BBjVector and remain useful for known-size data. BBj provides the `VECTOR()` function to convert arrays into BBjVectors when you need dynamic behavior.
2. **DIM Arrays:** Show `dim names$[2]` for string arrays and `dim values[5]` for numeric arrays. Explain: 0-based indexing, fixed size declared at creation, typed (string$ or numeric).

4. **Converting Arrays to BBjVector:** Show the `vector(array[])` function from RESEARCH.md. Use the verified example: `dim names$[2]`, populate, then `vect! = vector(names$[])`. Explain that VECTOR() was added in BBj 16.0.
5. **Comparison Table -- When to Use What:**

| Collection | Size | Types | Best For |
|------------|------|-------|----------|
| DIM array | Fixed at creation | Single type (string$ or numeric) | Known-size data, performance-critical loops |
| BBjVector | Dynamic | Mixed (any object) | General-purpose dynamic lists, BBjAPI integration |
| java.util.ArrayList | Dynamic | Mixed (any object) | Java library interop |
| java.util.HashMap | Dynamic | Key-value pairs | Lookup tables, configuration, any key-value data |

6. **A Note on String Templates:** Brief mention -- BBj also has string templates (`dim a$:tmpl$`) for structured byte data, used heavily in file I/O. Cross-link to the [File I/O chapter](/file-io) for coverage. This is not a collection type but new developers may encounter it in legacy code.

Legacy callout: "Reading Legacy Code: DIM Arrays as Collections"
- Before BBjVector, all dynamic data was stored in oversized DIM arrays: `DIM items$[999]` with a counter variable tracking actual usage
- String templates (`DIM rec$:"name:C(30),age:N(3)"`) were used as pseudo-records before custom objects
- The `VECTOR()` conversion function (BBj 16.0+) was added specifically to bridge legacy array code with modern collections
- If you see `REDIM` in code, it is resizing an array -- the closest legacy equivalent to adding items
