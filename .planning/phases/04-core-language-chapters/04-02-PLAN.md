**File 1: `docs/05-strings-and-numbers/01-string-basics.md`**

Frontmatter: `sidebar_position: 1`, `title: "String Basics"`

Content sections:
1. **Opening (2-3 sentences):** BBj strings use a `$` suffix by convention and are byte-oriented. The core operations -- length, extraction, trimming, case conversion -- are each a single function call.
2. **LEN() -- String Length:** Show `len(a$)` returning the byte count. IMPORTANT: Document the bytes-vs-characters gotcha from research Pitfall 2: `LEN()` returns bytes, not Unicode characters. For strings containing only ASCII characters, bytes equals characters. For non-ASCII, use `BBjString::length()` if you need character count. Show a brief example of the difference.
3. **Substring Extraction -- A$(pos,len):** Teach the 1-based position, length notation. Show:
   - `a$(1,5)` -- first 5 characters
   - `a$(7)` -- from position 7 to end
   - `a$(3,1)` -- single character at position 3
   Make clear this is NOT zero-based. This replaces MID$, LEFT$, RIGHT$ from other BASIC dialects.
4. **Concatenation:** The `+` operator concatenates strings: `a$ + " " + b$`. Brief, straightforward.
5. **CVS() -- String Cleanup:** CVS uses a bitmask to combine operations in one call. Table of values:
   - 1 = strip leading spaces
   - 2 = strip trailing spaces
   - 4 = convert to uppercase
   - 8 = strip non-printable characters
   - 16 = strip multiple consecutive spaces to one
   - 32 = convert to lowercase
   - 64 = swap commas and periods (locale)
   Show combining: `cvs(a$, 3)` strips both leading and trailing, `cvs(a$, 7)` strips + uppercase.
   Use the verified examples from RESEARCH.md.
6. **String Variables and the $ Suffix:** Brief note -- string variable names conventionally end with `$`. This is a naming convention inherited from BASIC. BBj also supports Object-typed variables (with `!` suffix) that can hold strings.

Legacy callout: "Reading Legacy Code: String Operations Across Generations"

- The main difference: older code may use all-uppercase (`LEN`, `CVS`) vs modern lowercase convention

**File 2: `docs/05-strings-and-numbers/02-searching.md`**

Frontmatter: `sidebar_position: 2`, `title: "Searching Strings"`

Content sections:
1. **Opening (2-3 sentences):** BBj has two string searching functions: POS() for literal substring matching and MASK() for regex pattern matching. Use POS() when you know the exact text to find; use MASK() when you need pattern-based matching.
2. **POS() -- Find Substring Position:** Core syntax `pos("find"=a$)` returns 1-based position or 0 if not found. Show the verified MONTUEWED example from RESEARCH.md.
3. **POS() Advanced Options:**
   - Search from a starting position: `pos("find"=a$, startPos)`
   - Search backward: `pos("find"=a$, -1)` -- backward from end
   - Count occurrences: `pos("find"=a$, 1, 0)` -- returns count, not position
   Use the verified backward search and occurrence count examples from RESEARCH.md.
4. **MASK() -- Regex Pattern Matching:** Explain that MASK() uses Perl 5 regex syntax. Show `mask(a$, "pattern")` returning 1-based position of first match (or 0). Use the verified config.bbj example from RESEARCH.md. Mention TCB(16) returns match length after a successful MASK() call.
5. **POS() vs MASK() -- When to Use Each:** Brief comparison table:
   - POS() for literal substring search (faster, simpler)
   - MASK() for pattern/regex matching (more powerful)
   - POS() returns position; MASK() returns position + match length via TCB(16)

Legacy callout: "Reading Legacy Code: String Searching Before MASK()"
- MASK() was added in BBj; earlier BBx/PRO/5 programs used POS() for everything
- Complex pattern matching was done with nested POS() calls and manual character scanning
- If you see multi-line POS() chains in legacy code, consider whether MASK() could simplify
