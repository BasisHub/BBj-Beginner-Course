# Phase 2: Structure - Research

**Researched:** 2026-01-31
**Domain:** Docusaurus 3.9.2 content reorganization, custom React homepage components, sidebar configuration, samples directory
**Confidence:** HIGH

## Summary

Phase 2 reorganizes the existing 5-section flat docs structure into 12 numbered chapter directories, adds three homepage React components (Hero, ChapterCards, HomepageFeatures), configures sidebar navigation with autogenerated categories, and creates a samples directory for runnable BBj code. Every pattern in this phase has a proven reference implementation in the sibling DWC Course repository (`BasisHub/DWC-Course`), which was examined in detail on 2026-01-31.

The DWC Course uses a specific architecture: `docs/index.md` with `slug: /` serves as the homepage by importing React components via MDX, each chapter lives in a numbered directory (`01-name/`, `02-name/`, ...) with an `index.md` entry page, the sidebar config defines categories manually with `autogenerated` items pointing to chapter directories, and samples live in a top-level `samples/` directory outside `docs/`. This pattern was verified against the live site at `basishub.github.io/DWC-Course/`.

Docusaurus 3.9.2 number prefix parsing (enabled by default) automatically strips `01-`, `02-` prefixes from doc IDs and URLs, meaning `docs/02-getting-started/index.md` gets doc ID `getting-started` and URL `/getting-started` without needing explicit `slug` frontmatter. However, the CONTEXT.md decision says to use `slug` frontmatter to keep URLs clean -- since number prefix stripping already does this by default, explicit `slug` frontmatter is only needed if the desired URL differs from the stripped directory name (e.g., if `04-upgrading-apps/` should map to `/upgrading-apps` but the directory is named differently).

**Primary recommendation:** Follow the DWC Course component-for-component. Every component, CSS pattern, and sidebar structure has been verified against a working build. The 3 existing content directories (getting-started, object-oriented, file-io, web-development) must be renamed and moved; introduction/ becomes the new homepage and a standalone intro page. Content within files stays unchanged -- only frontmatter and directory locations change.

### Pattern 1: MDX Doc as Homepage

**What:** Use `docs/index.md` with `slug: /` and `hide_table_of_contents: true` as the homepage. Import React components via MDX imports.

**When to use:** When the homepage should appear in the sidebar and use the docs layout.

**Example (verified from DWC Course `docs/index.md`):**

```mdx
---
sidebar_position: 1
slug: /
title: Introduction to BBj Development
hide_table_of_contents: true
---

import Hero from '@site/src/components/Hero';
import HomepageFeatures from '@site/src/components/HomepageFeatures';
import ChapterCards from '@site/src/components/ChapterCards';

<Hero />

<HomepageFeatures />

<ChapterCards />
```

**Key details:**
- `slug: /` makes this the root URL
- `hide_table_of_contents: true` removes the right-side TOC (homepage has no headings to track)
- `sidebar_position: 1` puts it first in sidebar
- No `src/pages/index.tsx` must exist (would conflict)
- React components are imported with `@site/src/components/` prefix

### Pattern 7: Number Prefix Parsing and Doc IDs

**What:** Docusaurus 3.x automatically strips number prefixes from doc IDs and URLs when `numberPrefixParser` is enabled (the default).

**How it works:**
- File: `docs/02-getting-started/index.md`
- Doc ID: `getting-started` (prefix `02-` stripped, `index` convention strips filename)
- Default URL: `/getting-started` (with `routeBasePath: '/'`)
- Sidebar reference: Use the stripped ID `getting-started` (or `{type: 'autogenerated', dirName: '02-getting-started'}` for the directory)

**Important:** When using `autogenerated` sidebar items, the `dirName` must use the FULL directory name including the prefix (e.g., `'02-getting-started'`), even though the resulting doc IDs have the prefix stripped.

### Pattern 8: Prev/Next Navigation

**What:** Docusaurus automatically generates prev/next links based on sidebar ordering.

**How it works:**
- Sidebar order determines the navigation chain
- Each doc gets automatic prev/next links at the bottom
- Override with `pagination_prev` and `pagination_next` frontmatter
- Set to `null` to disable (e.g., on the homepage)
- `pagination_label` controls the display text in the navigation button

**For this project:** Sidebar ordering should create a natural reading flow:
Homepage -> Running Samples -> Ch1 Introduction -> Ch2 Getting Started -> ... -> Ch12 Web Development

### Anti-Patterns to Avoid

- **Don't use `src/pages/index.tsx` alongside `docs/index.md` with `slug: /`:** Route conflict. The DWC Course does not have a `src/pages/` directory at all.
- **Don't use `_category_.json` files when sidebar config already defines categories:** The DWC Course has zero `_category_.json` files -- all category metadata is in `sidebars.ts`.
- **Don't put `slug` frontmatter on every doc:** Number prefix stripping handles this automatically. Only use `slug` if the desired URL differs from the stripped directory name.
- **Don't hardcode doc IDs with number prefixes in sidebar config:** Use `autogenerated` with `dirName` instead. The `dirName` uses the full directory name, but individual doc IDs are stripped.
- **Don't create chapter sub-pages in Phase 2:** Existing content moves into new directories, placeholder chapters get only `index.md`. Sub-pages are added in later phases.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Card grid layout | Custom CSS Grid | Infima `row`/`col col--4` classes | Built-in, responsive, consistent with Docusaurus ecosystem |
| Dark mode support | Manual `@media (prefers-color-scheme)` | Infima CSS variables (`--ifm-color-*`) and `[data-theme='dark']` selectors | Docusaurus handles mode switching; use its variables |
| Internal routing | `<a href="...">` tags | `@docusaurus/Link` component | Handles SPA routing, baseUrl, active state |
| Heading anchors | Custom anchor generation | `@theme/Heading` component | Generates consistent anchor IDs for linking |
| Sidebar generation | Manual sidebar item lists for each doc | `autogenerated` items with `dirName` | Automatically picks up new files, maintains correct ordering |

**Key insight:** The Docusaurus + Infima ecosystem provides layout primitives (grid columns), theme-aware variables, and routing components that handle edge cases (baseUrl, dark mode, SPA navigation). Custom CSS should only add component-specific styles (hero padding, card borders), never replicate framework functionality.

## Common Pitfalls

### Pitfall 1: Route Conflict Between Pages and Docs

**What goes wrong:** Having both `src/pages/index.tsx` and `docs/index.md` with `slug: /` causes a build error or unpredictable routing.
**Why it happens:** Both try to claim the `/` route.
**How to avoid:** Delete or ensure `src/pages/` is empty (it currently is). Use the MDX doc approach exclusively.
**Warning signs:** Build error mentioning duplicate routes.

### Pitfall 2: Broken Links After Content Move

**What goes wrong:** Moving docs from `getting-started/` to `02-getting-started/` changes the doc ID, breaking any internal links, sidebar references, or footer links.
**Why it happens:** Doc IDs are derived from file paths. Moving files changes IDs.
**How to avoid:** After moving content:
1. Update all `slug` frontmatter if URLs should be preserved
2. Update `sidebars.ts` to use new `dirName` values
3. Update footer links in `docusaurus.config.ts`
4. Run `npm run build` -- `onBrokenLinks: 'throw'` will catch any broken references
**Warning signs:** Build fails with "broken link" errors.

### Pitfall 3: Number Prefix Not Stripped from dirName

**What goes wrong:** Using `dirName: 'getting-started'` instead of `dirName: '02-getting-started'` causes sidebar to find no items.
**Why it happens:** `dirName` matches the actual filesystem directory name (with prefix). Only the generated doc IDs have prefixes stripped.
**How to avoid:** Always use the full directory name in `dirName` fields.
**Warning signs:** Empty sidebar categories with no items.

### Pitfall 4: Sidebar Position Conflicts

**What goes wrong:** Multiple docs in the same directory with the same `sidebar_position` or no position, causing unpredictable ordering.
**Why it happens:** Default ordering is alphabetical by filename. Number prefixes on files within a directory provide automatic ordering.
**How to avoid:** For Phase 2, each chapter directory has only `index.md` (no conflicts). When sub-pages are added in later phases, use number-prefixed filenames (e.g., `01-setup.md`, `02-syntax.md`) within chapter directories.
**Warning signs:** Sidebar items appear in wrong order.

### Pitfall 5: Missing sidebar_position on Homepage

**What goes wrong:** Homepage doc appears in wrong position or is not first in sidebar.
**Why it happens:** Without explicit `sidebar_position: 1`, the doc may sort alphabetically.
**How to avoid:** Set `sidebar_position: 1` on `docs/index.md` and reference it as `'index'` first in the sidebar config.
**Warning signs:** Homepage not appearing as first sidebar item.

### Pitfall 6: ChapterCards Linking to Non-Existent Routes

**What goes wrong:** Chapter cards have `to="/error-handling"` but the placeholder page has a different slug or hasn't been created yet.
**Why it happens:** Card slugs don't match actual doc URLs.
**How to avoid:** Derive card slugs from the actual doc IDs (which come from directory names with prefixes stripped). For `04-error-handling/index.md`, the URL is `/error-handling`.
**Warning signs:** Build succeeds but clicking a card shows 404.

### Pitfall 7: Footer Links Broken After Reorganization

**What goes wrong:** Footer links in `docusaurus.config.ts` point to old URLs like `/` and `/getting-started` that may have changed.
**Why it happens:** Footer links use `to:` paths that must match actual doc URLs.
**How to avoid:** Update footer links after reorganization. Test with `npm run build`.
**Warning signs:** `onBrokenLinks: 'throw'` catches these during build.

## Chapter Ordering Recommendation

| # | Directory | Content | Rationale |
|---|-----------|---------|-----------|
